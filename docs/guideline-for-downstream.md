## 0. 摘要與待辦

**變了什麼：** 觀念卡的某些主張（claim）現在可以附 `figures`：從 blog 複製來的圖（多半是論文的 Figure 或 Table 截圖），放在 `wiki/figures/<article>/`。圖是讓你讀這條主張時多一個可以看的參考。

**三個核心規則：**
1. **圖不是證據，只是參考。** 主張的依據永遠是主張的文字（`text`、`source_quotes`、`qualifiers`）。
2. **貼文要用圖，必須重製，不可直接複製貼上原圖。** 重製後的正確性由你這邊的審核負責。
3. **沒有 `figures` 的主張、不想用圖的貼文，完全不受影響。** 這是可選欄位，向下相容。

另有兩項較小的契約變更，見 §9：錨點「部落格推論」的定義擴充（9.1）、限定條件可引用圖說交代範圍（9.2）。

**待辦清單（細節見 §4、§9）：**
- [ ] 卡解析程式（`cardlib.py` 或同職責的檔案）：讀可選欄位 `figures`，提供圖檔的實際路徑；舊卡沒有這個欄位不得報錯。
- [ ] 寫貼文的規則文件（`references/anchor-writing-rules.md` 或同職責的檔案）：新增「參考圖」一節（§5 有可直接採用的規則草案）。
- [ ] 你的 `CLAUDE.md`：加入「卡上的圖只是參考、要重製」的不可違反規則。
- [ ] 寫貼文的 skill：選主張時，附圖的主張要實際看圖（用 Read 打開圖檔）；決定要不要做視覺、怎麼重製。
- [ ] 你的審核流程：新增「重製的圖 vs. 原圖、vs. 主張」的檢查項。

## 1. 背景：上游為什麼加這個

上游（本 repo，Stage 1）把 DataSci Ocean 的論文解析文章提煉成觀念卡。以前卡只有文字。但 blog 裡有些圖與表格很難用文字取代（架構流程圖、指標相關矩陣、結果比較表），做貼文時有圖可以參考會更有依據。所以上游讓主張可以附圖。

兩個 repo 的關係不變：你把上游 repo 當 submodule，只讀 `wiki/` 與 `docs/card-format.md`；單向、唯讀，不把問題退回上游。

## 2. 契約變更

### 2.1 檔案位置

```
wiki/
  concepts/<concept-id>.md          觀念卡（和以前一樣）
  figures/<article>/<檔名>           新增：主張附的參考圖（從 blog 複製）
```

`<article>` 是 blog 文章的 slug，用來避免不同文章都有 `figure1.png` 的檔名衝突。

### 2.2 主張上的 `figures` 欄位（可選）

```yaml
claims:
  - id: c5
    role: mechanism
    text: …（和以前一樣，純文字）
    source_quotes: ["…"]
    anchor_type: 設計參數
    qualifiers: []
    importance: 2
    status: normal
    figures:                                        # 新增，可選；一條主張最多 2 張
      - file: figures/adaptive-chunking/figure5.png   # 相對於 wiki/
        article: adaptive-chunking                    # 圖來自哪篇 blog
        src: figure5.png                              # 圖在 blog 裡的原檔名
        caption: "圖 5：Split-then-Merge 遞迴切分管線…（來源：原始論文 Figure 5）"   # blog 的圖說原文
        sha256: 3f2a…                                 # 圖檔雜湊
```

| 欄位 | 你要怎麼用 |
|---|---|
| `file` | 圖的位置，**相對於 `wiki/`**。實際路徑是 `<submodule 路徑>/wiki/<file>`。卡在 `wiki/concepts/`，所以從卡出發是 `../<file>` |
| `article`、`src` | 圖的來源，可用來回頭對照 blog |
| `caption` | blog 對這張圖的說明，常含出處（「來源：原始論文 Figure 5」）。**這是圖的描述，不是主張**，見 §3 |
| `sha256` | 複製當下的雜湊，上游用來偵測 blog 改圖。你可以用它做完整性檢查，但不是必要 |

同一張圖被同一張卡的多條主張用到，每條主張各列一筆，檔案只存一份。

## 3. 語意：上游保證什麼、不保證什麼

這一節決定你怎麼信任這些圖，請仔細讀。

| 上游保證 | 上游**不**保證 |
|---|---|
| 圖真的來自 blog 內文，位元組沒被動過；`caption` 是 blog 原文 | 圖上所有內容都被查證過。審查者（subagent）只核對「**這條主張提到的數字與語意**」和圖有沒有矛盾；圖上其他的格子、線條、標籤，沒有逐條對證 |
| 這條主張的文字與圖沒有矛盾（審查者實際看過圖，數字只讀圖上印出來的，不目測估算，並寫出圖上的位置與讀到的內容） | 圖可以直接用在貼文。圖多半是論文原圖，怎麼用（重製、標註出處）由你決定 |
| 主張文字不靠圖也讀得懂（獨立讀者審查時看不到圖） | 圖說（caption）的內容可當主張用。圖說是 blog 對圖的描述，沒有經過主張那套逐字引文與限定條件的審查 |

由此推出的使用原則：
- **主張的文字是你的上限。** 貼文裡的判斷、數字、結論，一律來自主張文字（加上它的 `qualifiers`）。圖幫你理解與設計視覺，不是新的資訊來源。
- **圖上有、但主張沒寫的內容，上游沒有查證。** 如果你的視覺重製了整張表或整張圖，其中主張沒提到的部分是「blog 圖上的內容」，不是「卡保證過的內容」，要靠你自己的審核對照原圖（§5）。
- **狀態規則照舊且延伸到圖。** 主張是 `pending_author_confirmation` 時，它的圖也不能用；`author_confirmed` 的主張，圖可用，寫法取保守。
- **限定條件不因為有圖而消失。** 用了附圖的主張，它的 `qualifiers` 仍必須在貼文裡一起帶出。圖不會取代限定條件；重製的圖若省略了圖上標明的範圍（例如表格只取一欄、圖例被拿掉），要確認沒有讓範圍看起來比實際更廣。

## 4. 你這邊要改什麼

下列檔名是上游對下游的假設（`cardlib.py`、`references/anchor-writing-rules.md` 是契約文件裡點名的）；如果你的檔案配置不同，對應到相同職責即可。

### 4.1 卡解析（`cardlib.py`）

- 主張物件多一個可選欄位 `figures`（清單，預設空）。每筆含 `file`、`article`、`src`、`caption`、`sha256`。
- 提供「圖檔實際路徑」的 helper（`<上游 submodule>/wiki/<file>`），並在取用時確認檔案存在；缺檔要明確報錯，不要靜默略過。
- 舊卡（沒有 `figures`）與沒附圖的主張必須照常解析。
- 在你「取一張卡的主張子集」的函式（依 `importance` 由上往下取）裡，附圖的主張帶著它的 `figures` 一起走。`pending_author_confirmation` 的主張被排除時，它的圖自然跟著被排除，不要另外保留。
- 選用：核對檔案 sha256 與 `sha256` 欄位一致，不一致就警告（代表 submodule 內容被改過）。

### 4.2 寫貼文的規則文件（`references/anchor-writing-rules.md` 或同職責檔案）

加一節「參考圖」，規則草案見 §5。

### 4.3 你的 `CLAUDE.md`

在「不可違反的規則」加一條，例如：

> 卡上主張附的圖（`figures`）只是參考，不是證據。貼文的內容只能來自主張文字與限定條件；要在貼文放視覺，必須重製，不得直接複製貼上卡上的圖檔；重製的圖要過我們自己的審核。

### 4.4 寫貼文的 skill

- 讀一條主張時，若有 `figures`，**實際看圖**（用 Read 打開圖檔），不要只看路徑或 caption。
- 決定要不要在貼文放視覺：圖能讓這個觀念更好懂就重製一張；不需要就不用。完全不用卡上的圖是合法的。
- 重製時遵守 §5。

### 4.5 你的審核流程

- 貼文若含重製的圖，審核者要同時拿到**原圖、主張文字（含 `qualifiers`）、重製後的圖**，檢查 §5 的項目。
- 這套審核要由你這邊獨立做，不要假設上游已經幫你查證了圖上的內容（見 §3）。

### 4.6 測試

- 解析：有 `figures` 的卡、沒有 `figures` 的舊卡、`figures` 指到不存在的檔案（應報錯）。
- 取主張子集：附圖的主張與它的圖一起被取到；pending 主張與它的圖一起被排除。

## 5. 重製圖的規則草案（可直接放進你的規則文件）

1. **不直接複製貼上。** 卡上的圖是 blog 從論文截來的，只能當參考，貼文裡的視覺要自己重製。
2. **內容以主張為準。** 重製的圖，其數字、標籤、比較關係要和**主張文字**一致。主張沒提到的圖上內容，除非你逐項對照原圖核對過，否則不要放進重製圖。
3. **不加新資訊。** 不因為圖上有就在貼文加入主張沒有的判斷、數字、結論。
4. **範圍不放大。** 重製時保留原圖標明的範圍與條件（資料集、模型組、設定、圖例）；主張的 `qualifiers` 照常帶出。
5. **出處。** `caption` 常含「來源：原始論文 Figure N」。貼文要不要標註出處、怎麼標，由你決定；建議標註，並避免把這張圖說成是我們自己做的實驗。
6. **圖說不是貼文文字。** 不要把 `caption` 整段搬進貼文。它沒經過主張那套審查。
7. **重製後自檢並過審核。** 逐項對照原圖：數字、單位、座標、圖例、標題；再對照主張文字。對不上的一律以原圖與主張為準修正。
8. **圖看不懂或太複雜時不用。** 寧可只用文字，不要重製出一張自己也無法保證正確的圖。

## 6. 什麼沒有改

欄位 `id`、`role`、`text`、`source_quotes`、`anchor_type`、`comparison_target`、`qualifiers`、`importance`、`status` 的語意都不變（只有 `anchor_type` 中「部落格推論」的定義擴充，見 §9.1；`qualifiers` 的引文來源多一種，見 §9.2）；`status` 的使用規則（`normal` 可用、`pending_author_confirmation` 一律不用、`author_confirmed` 可用且取保守）不變；錨點類型清單沒有新增。「卡是上限」原則不變：貼文內容是卡的子集。

## 7. 更新流程與注意事項

- 更新 submodule（`git submodule update --remote`）後，`wiki/figures/` 會出現新圖。圖是一般檔案（不是 Git LFS），單檔上限 2000 KB。
- 上游偵測到 blog 改了圖時，會重新複製並重審附這張圖的主張，你看到的是更新後的卡與圖。已經用了舊圖重製的貼文，要自行確認是否受影響。
- 你看不到、也不需要處理上游的審查過程；你只讀卡。發現卡或圖有問題，不要改上游的檔案，回報給人，由人在上游處理（單向原則不變）。

## 9. 其他契約變更（2026-10-24）

### 9.1 錨點「部落格推論」的定義擴充

| | 定義 |
|---|---|
| 舊 | blog 已明標為推論的內容 |
| 新 | blog 對原因或機制的解釋或推測，論文沒有實測驗證，**不論 blog 有沒有明標「推論」**。好壞、該不該、值不值得的評價仍是「部落格判斷」 |

原因：實務上 blog 常直接用肯定句解釋原因（例如「這個落差來自資訊密度」「輸掉的直接原因是剪枝預算」），沒有寫「推論」二字，但這些都是 blog 的解釋，不是實驗量到的結果，下游必須用保守語氣。舊定義讓這類句子無處可標，或被標成「部落格判斷」而與評價混在一起。

你這邊要做：
- 更新規則文件裡「部落格推論」的定義與寫法：寫成「blog 推測／解釋…」，不當成已驗證的事實，不用肯定的因果語氣。
- 既有卡不必改：舊卡標「推論」的都是明標的，新定義涵蓋它們。

### 9.2 限定條件可以引用圖說，但只限範圍

`qualifiers` 的項目多一個可選欄位 `source`：

```yaml
qualifiers:
  - text: 這個消融是在 MuSiQue 上做的
    source_quote: "表三 — 動態超邊建構中擴展跳數的消融實驗（MuSiQue）"
    source: figure_caption
```

- 沒有 `source` 的項目和以前一樣，`source_quote` 是 blog 內文的逐字原文。
- `source: figure_caption` 表示 `source_quote` 取自**這條主張自己附的圖**的圖說（blog 對圖的說明），只用來交代範圍：資料集、模型組、設定。結論與比較對象不會這樣補。
- 原因：論文導讀的表格，資料集與設定常只出現在圖說，正文沒寫。以前這類範圍卡不進主張，下游會看到「Recall@5 暴增 10.6 個百分點」卻不知道只在某個資料集上。
- **帶出規則不變**：使用這條主張，就必須帶出它的限定條件；限定條件的 `text` 是你要寫進貼文的範圍描述。

你這邊要做：解析限定條件時，把 `source` 當可選欄位讀（沒有就是 blog 內文）；若你的程式有驗證引文是否出現在 blog，對 `source: figure_caption` 的項目要改成比對圖說，或乾脆略過（上游已驗證）。
