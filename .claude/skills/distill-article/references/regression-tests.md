# 回歸測試

修改任何程式檢查或審查流程後必須重跑。檢查寫進程式後，要用「故意做壞的版本」驗證檢查真的抓得到。

## 1. 程式層（已自動化）

```
uv run python tests/test_stage1_programs.py
```

涵蓋 `scripts/` 的每支程式：每項檢查各有「故意做壞的版本」（必須擋下）與「正確的版本」（必須放行，測誤殺；`tests/fixtures/concepts/` 的每張卡都必須通過 `validate_card`）。測了什麼看執行輸出，每項一行 PASS／FAIL。新增檢查時，兩種版本都要加。

## 2. 審查者層（subagent，尚未自動化）

用「做出帶錯的卡」測審查者抓不抓得到，用「正確的卡」測誤殺率。目前只做過隨機驗證（對證者抓到措辭放大、錨點標錯、來源沒涵蓋、blog 算式矛盾），還沒有固定的壞卡集。建議的測試卡：

| 測試卡 | 預期 |
|---|---|
| 缺席型主張（「文章沒提到…」），但 blog 其實沒寫 | 對證者抓到 |
| 設計參數被標成實驗結果 | 對證者抓到 |
| 一句評價是卡自己加的，blog 沒有 | 對證者抓到 |
| 「最廣泛」寫成「幾乎都」 | 對證者抓到（範圍被放大） |
| 數字衍生計算錯誤（例如倍數相除） | 對證者抓到（用計算器） |
| 兩條主張的數字範圍互相矛盾 | 對證者抓到（互核） |
| 限定詞（如「同級距」）沒有定義 | 對證者標 minor |
| 來源原文只涵蓋主張的一半（漏掉否定或範圍詞） | 對證者抓到 |
| 引文單獨成立，但同段前一句限定了範圍 | 對證者抓到（paragraph 模式）；quote 模式要由全文審查抓到 |
| 限定條件寫在引文以外的段落 | 全文審查抓到 |
| 兩張卡的數字互相衝突 | 全文審查抓到 |
| 主軸機制只有靠讀者本來就懂某概念才成立 | 讀者抓到 |
| 卡用了背景詞（LLM、prompt）但沒解釋 | **必須通過**（測誤殺） |
| 一張正確且自足的卡 | **必須通過**（測誤殺） |
| 主張的數字和附圖對不上（例如把表格某格的數字抄錯一位） | 對證者判「矛盾」 |
| 附的圖和主張無關 | 對證者判「不相關」 |
| 標 `source: figure_caption` 的限定條件帶了結論或比較對象（超出範圍） | 對證者在 errors 記「夾帶blog沒有的判斷」 |
| 對證者判「一致」卻沒有寫出圖上位置與內容 | 程式擋下（已自動化） |
| 附圖正確的卡 | **必須通過**（測誤殺） |

做法：複製一張現有卡到暫存目錄，改出上述錯誤，各派一個全新審查者，確認抓到；再派一個審查者審原卡，確認不退回。

## 3. 未驗證事項

- 對證者只看引文與段落（paragraph 模式）時，斷章取義的抓取率；quote 模式更低，要靠全文審查補。
- 對證者讀圖的準確度（小字、密集表格、數字相近的欄）尚未量測；兩次附圖實跑共 30 筆全判一致，人的抽查尚待。
- 審查者之間可能有共同盲點（同一個模型）。人需偶爾冷讀抽查幾張卡，這是迴圈唯一的外部校準。
- 對證者、讀者各 5 輪的上限是否足夠；5 輪後是否仍會在錨點邊界反覆翻轉。
